# Verifying the COMSOL API names (⚠VERIFY)

_Generated by `comsol/python/sync_java_api_names.py` from `comsol/python/api_names.py`; do not edit by hand._

Every COMSOL feature type, property name, option value, default tag and variable name that this package could not confirm without a COMSOL installation is collected in **one** constants block (`API_NAMES`): `comsol/python/api_names.py` for Driver A, plus generated copies at the top of `comsol/java/BuildPinPeltier.java` and `comsol/java/RunVariants.java` for Driver B (spec §0 rule 1, §9.4).

## General procedure (COMSOL 6.3)

1. Open COMSOL, *Model Wizard > 1D*, add **Semiconductor** and **Heat Transfer in Solids**, *Study: Stationary*. (Or open any `comsol/models/stageN.mph` the builder saved.)
2. Create only the node in question with the **GUI action** below.
3. *File > Save As*, file type **Model File for Java (\*.java)**. Open the `.java` file in a text editor.
4. Search for the **Java pattern** below. `<HERE>` marks the position of the name; the string COMSOL wrote there is the true name for your version.
5. If it differs, put it into `config/api_names_override.yaml`, for example `FEAT_SRH: "TrapAssistedRecombination"`. Then run `python comsol/python/sync_java_api_names.py`, which also refreshes the Java copies. No code edits are needed.

When COMSOL rejects a name, both builders stop immediately with `ApiNameError: COMSOL rejected API name <CONSTANT> = '<value>' ...` and a link to the matching entry below. Each stage saves `comsol/models/stageN.mph`, so the failing node is easy to inspect.

Tip: *Developer > Record Method* (Application Builder) records the Java calls of GUI actions live, which is faster than saving a whole `.java` file for each check.

## How to read each kind

- **feature**: Create the node in the GUI, save as Java, and read the second argument of the matching `create("tag", "<TYPE>", ...)` call.
- **property**: Change the setting in the GUI, save as Java, and read the first argument of the matching `set("<PROPERTY>", ...)` call.
- **value**: Choose the option in the GUI, save as Java, and read the second argument of the matching `set("property", "<VALUE>")` call.
- **tag**: The default child tag COMSOL gives the node; visible in the Save-as-Java output (`feature("<TAG>")`) and in the Model Builder with *Show > Tags* (or the node's Properties window).
- **variable**: Variable name in the Results expression list (Add/Replace Expression); in the GUI hover the entry or check the *Equation View* of the interface. The builder also probes the candidates listed here after the first solve and logs the one that works.

## Notes on units (also worth confirming once)

- Boundary heat source on a **point** of a 1D component with a cross-sectional area: the builder assumes `Qb` in W/m^2 (per unit cross-section), so `-abs(J_X)*Pi_nc` is dimensionally correct. Check the unit shown next to *Q_b* in the GUI.
- `I_TERMINAL` should already include the cross-sectional area `Ac` (A, not A/m^2). Stage 4 logs the ratio `|I_TERMINAL|/(Ac*|J_X|)`, which should be 1.
- Energies (`semi.Ec`, ...) are exported with unit `eV`.
